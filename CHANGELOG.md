# Improvement Changelog

Every row is one Run of the same 17 Cases with the same scorer (`pnpm eval`), model `claude-sonnet-5`, effort `medium`. "Actionable" is the primary metric (verdict + hazard right, and any required fix proven by the harness on a fresh database). Evidence links point at files in `results/`.

| Stage | What was tried and why | Evidence | Decision / learning |
|---|---|---|---|
| **Baseline** | One prompt with the case files, the hazard definitions and the output schema. No tools. The fairest "reasonable basic way": same model, same inputs. | [`results/iter0-baseline/baseline.md`](results/iter0-baseline/baseline.md) — actionable **13/17 (76%)**, verdicts 15/17, fixes proven 5/7, **2 false "fix verified" claims**, 2 reviews citing durations that were never measured. $0.21 total, 11 s/case. | Stronger than expected: it recognises textbook migrations from their text. The misses are exactly the data-dependent ones (a `varchar` cap that fits, dropping an index no query uses), a fix with a **syntax error** (`VALIDATE CONSTRAINT` without `ALTER TABLE`, case 10) and a batched rewrite that still stalls the writer (case 05). It also *claims* measurements it cannot have made. Established the starting point and drove two eval changes: harness-proven fixes as part of the primary metric, and the grounded-numbers check. |
| **Eval change (before Iteration 1)** | My first 12 cases were all recognisable from SQL alone, and the baseline scored 12/12 on verdict. Added five "twin" cases where identical-looking SQL is safe or unsafe depending only on the data, and made the eval re-run every shipped fix itself. | Twin cases `13`–`17`; baseline drops from 12/12 to 15/17 on verdicts and to 13/17 actionable once fixes are proven rather than believed. | A metric the baseline can saturate measures nothing. Kept. |
| **Iteration 1 — Executor with a real simulator** | One agent, five tools (`inspect_schema`, `run_sql`, `explain_query`, `simulate_migration`, `verify_fix`), no Planner, no Verifier. The hypothesis: the missing ingredient is measurement, not reasoning. | [`results/iter1-executor-only/gatekeeper.md`](results/iter1-executor-only/gatekeeper.md) — actionable **17/17 (100%)**, fixes proven 7/7, 0 false claims, 53/54 cited durations grounded (the one miss is `0.06ms` rounded from `0.058`). $0.39 total (~$0.02/case), 29 s/case. | The whole gap closed with one agent and a simulator. The twin cases are trivial once you can run `max(length(email))` or watch the writer. Kept as the core. |
| **Harness fix (found by Iteration 1's smoke run)** | The first smoke run spent 7 simulations and $0.37 on one case because `LONG_TRANSACTION` measured total wall time, so a correctly batched backfill (4 s total, 80 ms per transaction) kept failing verification. Changed the measurement to the longest open transaction from `pg_stat_activity.xact_start`. | Smoke trajectory `trajectories/smoke/04-…/executor.jsonl` (7 tool calls, fix "NOT verified"); after the fix the same case takes 3 tool calls and $0.04. Test: `simulate.test.ts` "a whole-table UPDATE is one long transaction; the same backfill batched … is not". | An agent loop amplifies harness bugs: the model kept doing the right thing and the tool kept telling it it was wrong. Verify the verifier first. |
| **Iteration 2 — + blind Verifier** | Second agent that sees only the case and the Executor's *claim*, reproduces the evidence on its own fresh database, and can reject (ADR-0002). Hypothesis: the Executor is right on average but not reliably, and a rejection loop turns variance into reliability. | [`results/iter2-executor-verifier/gatekeeper.md`](results/iter2-executor-verifier/gatekeeper.md) — actionable **17/17**, fixes proven 7/7, 0 false claims, 88/92 durations grounded. **$1.00 total (2.6×), 62 s/case (2.1×)**. Two rejections, both correct: on case 08 the Executor first called `DROP COLUMN` **SAFE** and on case 04 it shipped a fix that silently dropped the `NOT NULL` and the default while claiming `fix_verified: true` (`trajectories/iter2-executor-verifier/{04,08}-*/orchestrator.jsonl`). Both were corrected on retry. | Same headline score, but without the Verifier this run would have delivered one wrong verdict and one wrong fix to the DBA. Iteration 1's 17/17 was partly luck. Kept: reliability is what a gate is for, and $0.06/case is still ~400× cheaper than the 25 minutes it replaces. Also found a scorer bug: when the original migration itself fails there is no end state to compare a fix against (case 15) — schema equivalence is now skipped in that situation. |
| **Iteration 3 — + Planner** | A first role that inspects tables, indexes and current plans and writes a measurement plan for the Executor. Hypothesis: a plan makes the Executor's tool use shorter and more targeted. | [`results/iter3-full-pipeline/gatekeeper.md`](results/iter3-full-pipeline/gatekeeper.md) — actionable **16/17**, verdicts 17/17, fixes proven 6/7, **$1.56 (1.6× iteration 2), 96 s/case (1.5×)**, 1 escalation. On the 10 cases shared with iteration 2 the Planner did shorten the Executor (5→3 tool calls on 04 and 08) but its own turns cost more than it saved: +17 % cost, +22 % time for the same 10/10. The miss (case 11) is a judgment call — "this index is used, do not ship" with no rewrite offered. The escalation (case 15) was the Verifier catching fabricated fix evidence, then the retry running out the 6-minute cap. The first attempt at this run also exposed an infrastructure failure: seven cases hung ~15 min each on API requests that the SDK retried silently past the time cap; fixed with a hard 120 s request timeout and error events in the trajectory, then re-run. | **Removed.** No decision the Planner made changed an outcome; everything it found, the Executor found with one `inspect_schema` call. Purposeful components only — a role must change a result to earn its cost. |
| **Final — Executor + blind Verifier** | The configuration the evidence supports, re-run from scratch on the final code (`pnpm eval --run-id final`). | [`results/final/comparison.md`](results/final/comparison.md) — baseline actionable **15/17**, gatekeeper **17/17**; fixes proven 7/7 vs 7/7; false claims 1 vs 0; $0.20 vs $0.67 total; 8 s vs 53 s per case. | Main contribution: **a real simulator in the loop** (iteration 1 closed the whole gap on its own); the Verifier is what makes that result repeatable rather than lucky. Everything else — the Planner, the extra prompt words — was noise. |
